## Resolution (2026-08-05)

Resolved interactively with Alex via `/ungate`, run out of order at Alex's explicit request (this was not the earliest open gate — G-022 was — but Alex chose to deviate from the skill's default oldest-first ordering for this session).

**Investigated first: Coder (coder.com/solutions/workspaces), per Alex's specific question.** Coder is a self-hosted platform for provisioning dev/agent workspaces from Terraform templates, and its **Prebuilt Workspaces** feature is a real, direct answer to this gate's pool/pre-warm question — an automatically-maintained pool of already-built workspaces, cutting provisioning from minutes down to under a minute. But two costs make it a poor fit here: (1) Prebuilt Workspaces requires a **Premium license** (contact-sales, no published price) — not available on Coder's free Community/OSS tier; (2) adopting it means standing up and operating Coder's own control plane (server, database, provisioner) on infrastructure AWM owns, replacing the current CCR surface entirely, for a solo-dev/single-repo usage volume. Rejected as disproportionate.

**Investigated second, and adopted: Anthropic's own `self_hosted` Managed Agents environment type** (`platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes`), distinct from the `type: cloud` scheduled-routine surface G-034 examined (which really does have zero image/persistence lever — that finding stands unchanged). Under `self_hosted`, Alex runs a worker process (the `ant` CLI, or an SDK worker — both officially supported, `ant beta:worker poll` is a single command) on infrastructure he owns. The worker polls Anthropic's session queue and, per claimed session, spawns a container from a **custom image** (the docs' own documented pattern: `FROM your-base-image` + a `spawn.sh` that does `docker run --rm ... your-image`). This resolves the open question directly and more cheaply than Coder: it doesn't need a pool of N idle sandboxes the way Coder/Daytona's prebuild features do, because a `docker run` from an already-built image is already fast — the expensive work (pgvector build, warm pnpm store) moves to image-build time, which happens once, not every session. Official integration guides exist for Daytona/Modal/Cloudflare/E2B/Vercel/AWS/GKE if a pooled multi-tenant fleet is ever wanted later, but plain Docker on one host is sufficient for now.

**Decision: adopt the `self_hosted` environment type, spike it first before migrating any real session.** The real cost this trades in is a new maintenance burden the current CCR surface doesn't have — an always-on host Alex owns, its own security/patching/egress posture — replacing a zero-maintenance managed surface with one more thing to operate. Given that tradeoff, and that this is genuinely new (nothing in this repo has used `self_hosted` before), Alex chose to spike the mechanism end-to-end on a throwaway host before committing to migrating real interactive/nightly-executor sessions off CCR. `infra/session-bootstrap.Dockerfile` — removed post-G-034 because the old CCR surface had nowhere to plug it in — is exactly the right artifact for this surface; T-126 recreates and extends it (also baking in a warm pnpm store, not just pgvector) rather than restoring the deleted file verbatim.
