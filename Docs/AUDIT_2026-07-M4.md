## 3. Deep-dives

### 🔍 M4.5 component directory: `IMPLEMENTATION_NOTES.md` contradicted itself — fixed by this audit

The directory-organization story had two passes: an intermediate `primitives/`/`feedback/`/`layout/` split that left `Button`/`Card`/`IconButton`/`EntityAvatar` at the component root, then a follow-up ("M4.5 polish", branch `refactor/component-reorg`) that committed fully to by-kind (`buttons/`, `inputs/`, `surfaces/`, `feedback/`, `overlays/`, `layout/`, `utilities/`). **The live tree matches the by-kind pass.** `IMPLEMENTATION_NOTES.md` still carried a stale section describing the intermediate pass as current, directly contradicting its own correct, later section describing the same reorg. Corrected in this audit — the stale section now points at the correct one instead of restating wrong information.

### 🔍 M4.2: the `Link` button is not a documented no-op — it doesn't render at all

`IMPLEMENTATION_NOTES.md` described the `Link` button in `EntityActionBar` as a deliberate no-op (`onClick={() => {}}`), retained for a future search-popover wiring. Current code renders only `Create` and `Dismiss` — no `Link` button exists in the DOM. Commit `47ebd1a` ("review: M4.2 post-review fixes — correctness, dead code, and token compliance", 2026-04-26) removed it outright. The `onLink` prop is still retained in `EntityActionBarProps` exactly as documented (so the "stable call site" part was accurate) — only the "still rendered as a no-op" part was stale, by one commit. `EntityActionBar.test.tsx` correctly tests only "renders Create and Dismiss buttons" — the test matches reality; the prose didn't. Corrected in this audit.

### 🔍 M4.2: "orphaned entity marks removed on re-scan" — confirmed exactly as documented

`IMPLEMENTATION_NOTES.md`'s spec-deviation note (marks that lose their backing entity on re-scan are deleted rather than downgraded to `unlinked`) is verified accurate in `extensions/EntityHighlight.ts`'s `setEntitySpans`: the transaction strips every non-`unlinked` mark in range, then rebuilds only from spans present in the fresh server response — there is no "was this previously confirmed but now missing" downgrade path. No correction needed.

### 🔍 M4.2: server-side tests could not be executed (no Docker in this audit environment)

`entity.service.test.ts` / `entity.integration.test.ts` are meaningful by static read — 12 `it()` blocks total covering match accuracy, ambiguity, dismissal, and router-level entity creation — but were not run here (`docker compose ps` fails: no Docker daemon in this sandbox). The web-side 262 tests, which do exercise the entity-linking UI (`EntityActionBar`, `DetectedEntitiesPanel`, `EntityQuickCreatePopover`, the `EntityHighlight` extension), did run and pass. Re-run the server suite with Docker available before treating M4.2's server-side coverage as independently confirmed rather than "documented and plausible."

### 🔍 M4.2's archived `PLAN.md`/`REPORT.md` document a *different, later* effort — the original milestone's report only survives in git history

The most consequential finding. `Docs/milestones-archive/M4.2/PLAN.md` (moved from `Docs/milestones/M4.2/` as part of this same doc-cleanup pass) is titled **"M4.2: Session Editor Visual Polish,"** branch `feat/session-log/editor-polish` — not the entity-detection-and-linking milestone PT1.md's checkbox describes.

What happened, per git history:
- `b2d9123`→`212930d` is the **original M4.2**: entity-linking, CP-1 (schema migration) through CP-9 (save-time validation warning), embedded "Agent Report" showing all 9 checkpoints done, 440 tests passing (241 web, 199 server).
- `47e249a` ("docs(M4.2): replace plan + design spec for editor polish", 2026-04-26) **overwrote** `PLAN.md`/`DESIGN_SPEC.md` in place with an unrelated 7-checkpoint visual-polish follow-up plan.
- `65cbdcd` added a `REPORT.md` for *that* polish pass — meaning the original entity-linking M4.2 never got a standalone `REPORT.md` at all; its only report is the embedded section in a `PLAN.md` revision that no longer exists in the working tree (recoverable via `git show 212930d:Docs/milestones/M4.2/PLAN.md`).

A reader opening `Docs/milestones-archive/M4.2/{PLAN,REPORT}.md` would reasonably — and incorrectly — conclude that's what M4.2 delivered. **Corrected in this audit**: both archived files now carry a note at the top pointing to this finding and the git-recoverable original.
